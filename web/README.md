# Palisade admin app

The React admin UI (#358). Built with Bun into `static/app/dist` and served by
Go at the admin root behind the admin session (`internal/ui/app.go`); the
sign-in page is its own build in `dist/login`.

```bash
make web               # from the repo root: install + build (make build runs it too)
bun run dev            # Vite dev server against a local Palisade (see below)
bun run test           # all tests once
bun run test:watch     # re-run on save
bun run test:coverage  # with coverage (what CI runs, via make web-check)
bun run typecheck
bun run smoke          # after a build: the real dist/ renders, no library names left
bun run new:test <component|query|page> src/features/<area>/<Name>.tsx [route]
bunx playwright test   # role sweep in a real browser (make e2e builds first)
```

## Folder structure

```
web/
├── build/              Vite plugins that fit the build to the Go server (incl. unbrand)
├── scripts/            dev scripts (new-test.ts)
├── test-templates/     starting points for new tests (bun run new:test)
└── src/
    ├── main.tsx        entry: query client, router, toaster, CSP nonce
    ├── router.ts       router setup shared by main.tsx and tests
    ├── index.css       Tailwind + ledger theme + shadcn token mapping
    ├── routeTree.gen.ts  generated by the router plugin (committed, don't edit)
    ├── routes/         TanStack file routes: URL -> page. Thin: params,
    │                   search-param validation, then render a feature page.
    ├── features/       one folder per admin area
    │   └── services/   (example)
    │       ├── api.ts            query keys + useQuery/useMutation hooks
    │       ├── ServicesPage.tsx  the page a route renders
    │       ├── ServiceForm.tsx   parts used only by this area
    │       └── *.test.tsx        tests next to what they test
    ├── components/
    │   ├── ui/         shadcn components (generated: bunx --bun shadcn@latest add <name>)
    │   └── layout/     Shell (sidebar, top bar, footer), Page, PageHeader, Card,
    │                   Grid, FormRow: shared page structure; Fallback (404, error)
    ├── lib/            app-wide code: api client, boot (session values), utils
    └── test/           test setup and helpers (never imported by app code)
```

Rules of thumb:

- Code used by one area lives in that area's folder. Move it to
  `components/` or `lib/` when a second area needs it, not before.
- Routes stay thin so pages can be tested without the router.
- Every request goes through `lib/api.ts` (CSRF, errors, session expiry).
- Role checks in the UI use `can()` from `lib/boot.ts`. They only hide
  controls; the server enforces every role.

## Tests

Vitest + Testing Library in jsdom. A test file sits next to the file it
tests: `ServiceForm.tsx` -> `ServiceForm.test.tsx`.

Start from a template rather than a blank file:

| Template | For | Helper |
|---|---|---|
| `component` | presentational parts: props in, markup and callbacks out | `renderWithProviders` |
| `query` | anything that reads or writes through the API | `renderWithProviders` + `mockApi` |
| `page` | a route: loads, URL search params, role on the whole page | `renderRoute` |

Helpers in `src/test/`:

- `renderWithProviders(ui)`: renders with a fresh query client (no retries, no
  shared cache) and returns `user` (user-event) with the usual queries.
- `renderRoute("/services/3")`: the real router at that URL, under the admin base path.
- `mockApi({ "GET /api/v1/x": data, "POST /api/v1/x": (req) => reply(201, ...) })`:
  replaces fetch. A request with no matching route fails the test.
  `pending` holds a request open (loading states); `calls(key)` lists what
  was sent, with parsed JSON bodies and headers.
- `asRole("viewer")` / `setBoot({...})`: change what Go rendered for one test.

`setup.ts` resets mocks, stubbed globals and boot values after every test.

What every feature's tests cover:

1. Loading, empty and error states. A failed read shows an error (`role="alert"`),
   never an empty list, the same rule as the Go UI's DB-failure tests.
2. Writes send the right body and refresh what they change.
3. Server field errors (`fields` in the JSON error) appear on the form.
4. Write controls are hidden from roles that can't use them.

Query elements by role and accessible name (`getByRole("button", { name: /save/i })`),
not by class or test id, so tests also check accessibility. No snapshot tests.

`src/csp.test.tsx` fails when a component injects a `<style>` without the
CSP nonce. Add new components that inject styles (overlays, toasts) to it.

## Role sweep (e2e)

`make e2e` (from the repo root; first run `bunx playwright install chromium`)
builds the binary, starts it on a temp DB and port 0 with one of each record,
and signs in a viewer and an admin through real invites (`e2e/setup.ts`).
`e2e/roles.spec.ts` then opens every page as each role, presses every button,
menu item and switch one dialog or menu deep, and fails on any 403: a control
the role can see but whose route it can't use, or a read it can't make.
Writes the role may use do run, except sign-out, device and credential
changes and calls to other servers. Add a new page to its `pages` list.

## No library names in the build

The built app doesn't name what it's made of. Files are hash-only, the mount
is `#palisade`, and `unbrand` in `build/palisade.ts` renames what React,
TanStack, sonner and shadcn leave in the output, React DevTools' hook
included. The build fails when a rule stops matching or a library name is
left, so after adding or upgrading a dependency, add the rule it asks for
and run `bun run smoke`.

## Dev server

1. `make web` once, so Palisade has an `index.html` to render.
2. Run Palisade on `:8080` (or set `PALISADE_URL`).
3. `bun run dev`, open `http://localhost:5173/admin/login` and sign in, then
   `http://localhost:5173/admin/`.

Vite proxies every `/admin` path except the app to Palisade and copies the
session values from the page Go renders for the same cookie.
