# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Palisade** is a single-binary Go WAF + reverse proxy: embedded Coraza v3 (OWASP CRS), Echo v5 for HTTP/routing (`*echo.Context`; Echo is only a handler, `internal/app` owns every `http.Server`, issue #277), a SQLite store (pure-Go modernc; MySQL/Postgres were removed in #300), and an HTMX + Tailwind admin UI served from the same binary.

Naming: module/binary/service/user are `palisade`; data `/var/lib/palisade`, key `/etc/palisade`, logs `/var/log/palisade`, metrics `palisade_*`, `Server` header says `Palisade`. The repo was renamed from `coraza-waf-mod` to `palisade-waf` after v2.5.0; release assets are `palisade-waf-linux-*` (`ASSET` in Makefile, `PACKAGE_NAME` in `ci.yml`, `ASSET_NAME` in `install.sh`). `install.sh` pins with `PALISADE_VERSION`, supports v2.5.1+ only. Pre-rename GHCR images stay at `ghcr.io/sinhaparth5/coraza-waf-mod`. Only the Coraza *engine* keeps the Coraza name.

## Commands

Requires **Go 1.27+**.

```bash
make build       # go generate (minifies JS) + go build -> ./palisade
make generate    # regenerate minified JS only
make css         # recompile Tailwind (standalone CLI into .cache/, no Node) — output is committed
make icons       # subset the hugeicons font to the hgi-* names in use — output is committed
make test        # go test ./...
make bench       # proxy pipeline benchmarks -> bench.txt (see BENCHMARKS.md)
make fuzz        # every Fuzz* target for FUZZTIME (default 30s) each
make lint        # golangci-lint run ./... (.golangci.yml, version pinned in LINT_VERSION)
make dist        # cross-compile linux/amd64, linux/arm64 (CGO_ENABLED=0)
make tag VERSION=v1.0.0  # roll CHANGELOG, commit, tag, push -> release workflow
```

- Single test: `go test ./internal/proxy/ -run TestName -v`.
- **Never bare `go build` after editing JS** — `go:generate` (the `tools/minify` minifier) only runs via `make build`/`make dist`/`make generate`.
- `make build`/`make test` set `core.hooksPath .githooks` (pre-commit runs lint). `git commit --no-verify` skips it once.
- **Do not start the server** (`go run .`, `make run`) unless the user asks each time; verify with throwaway `go test` files and delete them after.
- Run `gofmt` and `make lint` on changed Go files. Tests are table-driven; add cases next to existing ones.
- Lint suppressions the presets don't cover get a same-line `//nolint` with a short reason (see `internal/storage/db.go`). Besides `standard`, lint runs `gosec` (G104 off: errcheck covers it), `bodyclose`, `errorlint`, `noctx`, `sqlclosecheck` and `rowserrcheck` (issue #278); tests skip gosec/noctx/bodyclose. Use `errors.Is`/`errors.As`, `...WithContext`/`...Context` calls and `defer rows.Close()`.
- Admin UI handler tests use `newAdminEnv` (`internal/ui/harness_test.go`): real handler + session + CSRF over temp SQLite. Use `env.do(method, path, form(...))`, don't call handlers directly.
- DB-failure paths: storage tests call methods on a closed DB (`closed_test.go`); UI tests drop tables under a live handler with `dropTables(t, env.dbPath, where)` (`api_dberr_test.go`) and expect a 5xx or `HX-Retarget`, never a 2xx with empty data.
- Storage tests get their DB from `openTestDB(t)` (temp SQLite).
- CI (`ci.yml`): `lint` and `test` (`-coverpkg=./...`, Codecov) gate `release` and `docker`. `codeql.yml` and `govulncheck.yml` run separately; `fuzz.yml` runs `make fuzz` weekly and on dispatch, uploading failing inputs (issue #265). A parser of untrusted input gets a `Fuzz*` target (`make fuzz` finds it by name); commit any crasher under `testdata/fuzz/` with the fix. Every `uses:` is pinned to a full commit SHA with the version in a trailing comment (issue #276; Dependabot bumps both), every workflow has top-level `permissions: contents: read` with per-job widening, and checkouts set `persist-credentials: false`.
- Run `go test -race` on packages where you touched shared state or a `Reload*` swap.
- Reviews follow `REVIEW.md` (every finding needs a concrete input/state → breakage scenario).

**CLI flags** — there is no config file; every bootstrap setting is a flag (`serve` in `internal/app/serve.go`), every runtime knob lives in the DB and is edited in the admin UI.

**Subcommands**: `prune [--retention d] [--vacuum]`, `setup --admin-email ...` (password on stdin, idempotent), `config export [--out f] | import [--replace] f` (needs `--db-key-file` for sealed secrets), `gencert --hosts ...`, `healthcheck [--url]` (scratch image has no curl), `--version`.

## Request pipeline

`internal/proxy/handler.go` `Handle`, in order: IP blocklist → geo blocklist → bot challenge gate → global rate limit → per-service rate limit → maintenance / waiting room → Coraza WAF → reverse proxy.

- **Maintenance and waiting room** (issue #198, `proxy/gate.go`, `security/waitroom`, table `service_gate`, on `Service.Gate`): skipped for open paths and trusted IPs. Maintenance is a 503 with `Retry-After`; `?palisade_bypass=<token>` sets `cz_bypass` and redirects with the token stripped. Waiting room tickets ride in `cz_wait_<id>`, HMAC'd with the challenge secret over service + ticket + `ratelimit.ClientKey`. Rooms live in `Handler.gates`, outside the registry, so `Reload` doesn't empty the queue. Queue state is bounded (`MaxQueue`, `MaxPerKey`, `QueueTTL`). Both log unblocked (`logChallenged`), so queue polls never touch autoban or JA4 reputation.

- `Handle` canonicalizes `r.URL.Path` first (`canonicalPath`: `//` collapsed, dot segments resolved, trailing slash kept, issue #310), so every path check and the backend see the same path; the WAF still gets the raw `RequestURI`. Never match on the raw path.
- IP/geo run **before** the challenge so a banned IP gets 403, not an endless challenge redirect.
- WAF runs **after** the challenge on purpose: autoban needs unsolved-challenge points to ban a new attacker before any WAF verdict exists.
- `openPaths` (`/robots.txt`, `/sitemap.xml`, `/sitemap_index.xml`, `/llms.txt`; bodiless, query-less GET/HEAD) skip everything but the WAF, even for banned IPs.
- `canonicalRedirect` 301/308s host aliases to the canonical host before any other stage.
- Unknown `/_cz/*` requests (e.g. `HEAD /_cz/challenge` — Echo doesn't route HEAD to GET) are 404'd, never challenged or proxied.
- Logging is fire-and-forget: `DB.QueueRequest` → buffered `logQueue` (10000) → one `runLogWorker` goroutine, which also fans out to broadcast, webhook, autoban, threat score and access log hooks. Hooks run on that goroutine, so keep them in-memory; spawn goroutines for slow work.
- `Server: Palisade` is forced in both `handler.go` and `services/registry.go`'s `ModifyResponse`.
- `proxy.responseWriter` must explicitly implement `Hijack` and `Flush` or WebSockets break.
- `proxy.ConnLimiter` (`--max-conns-per-ip`, issue #272) wraps the TCP listeners below TLS and closes connections over the cap at accept, keyed by `ratelimit.ClientKey`. Trusted proxies, Cloudflare peers, loopback and trusted IPs are exempt; QUIC and the admin listener are not capped. `hardenServer` sets HTTP/2 `MaxConcurrentStreams` (100, same for HTTP/3 via `quic.Config`).
- Client IP: always `proxy.ClientIP` (CF header only from Cloudflare peers, XFF only from `--trusted-proxies`, walked from the right), **never** echo's `c.RealIP()`.
- Backends get `X-Forwarded-For`/`X-Real-IP`/`CF-Connecting-IP` rewritten from that resolved IP (`forwardClientIP`, applied to a clone so `captureHeaders` still logs what the client sent). The stock Director keeps client copies, so never forward `r` directly.
- Trusted IPs (Settings, `services.Registry.Trusted`) skip IP/geo/challenge/rate-limit **and the WAF** on every path, and never trip honeypots.
- IPv6 clients are keyed by /64 via `ratelimit.ClientKey` for rate limits, autoban, bans and threat-score cache. New per-client counters must use it; logs and manual rules keep the exact address.

## Services and routing

- Services live in the DB only (`/admin/services`); `services.Registry` holds them plus one load-balancing `pool` per service, rebuilt wholesale by `Reload(db)` on every change.
- `Match(host, path)`: prefix matches first (longest wins, prefix stripped before proxying), then host. Returns nil when nothing matches — no fallback to the first service; unmatched traffic is logged as app `VPS`. A default backend is an explicit Prefix `/` service.
- Every host lookup goes through `Registry.hosts` (host + `HostAliases` → service), never `Service.Host`. `services.ValidateHosts` is the single hostname check.
- `services.Validate` blocks cloud metadata endpoints by host and resolved IP; private backends are allowed on purpose. The same check runs again at connect time on the IP dialed (`security/egress`, issue #270): `backendTransport` and every outbound client use `egress.Dialer`/`egress.Client`, so a new outbound `http.Client` must be built with `egress.Client`, never a bare `&http.Client{}`.
- Multiple backends: `Backend` + newline-separated `ExtraBackends`, `round_robin`/`least_conn`. Passive health by default (10s cooldown); with `health_path`, active checks gate re-entry. All backends must share a base path. Readiness (`/_cz/readyz`) ignores backend health.
- **Varnish** (per-service "Cache"): client → WAF → varnishd `127.0.0.1:6081` → WAF cache-return listener `127.0.0.1:6082` → backend. The VCL has one backend and never changes per service; per-service settings travel as `X-Cache-*` headers. Everything is loopback-only by design. `install.sh` embeds the VCL in a heredoc — edit `deploy/varnish/default.vcl` and the heredoc together (`TestInstallVCLMatchesDefault` enforces byte equality). Purge ban expressions are guarded only by `safeServiceNameForBan`/`safePurgePath` (Varnish ban grammar has no escaping).
- Varnish failures fail open: a dial error, or a 503 the VCL's `vcl_backend_error` marks with `X-Cache-Fetch-Error`, is served from the backend by a `stripPath` pool (the Director already joined the base path) and logged as cache status `ERROR` (Logs "Cache errors" filter). install.sh raises varnishd's 8 KiB header limits; an oversized backend header was the static asset 503 in issue #212.
- Per-service path rules (`cache_rules`, `services/cacherules.go`, issue #212): `cache /p` or `bypass /p`, longest prefix wins, matched on the service path before the base-path join. Bypass skips Varnish in the Director; cache sends `X-Cache-Rule: cache`, which the VCL treats like a static asset (cookies and Set-Cookie dropped, Authorization still passes).
- **HTTP/3**: `--listen-h3` + per-service opt-in, both gated by `Registry.HTTP3Host` (Host-matched services only). `Allow0RTT` must stay explicitly `false` (quic-go enables it when `QUICConfig` is nil).
- TLS certs by SNI: per-service custom cert → autocert (if in `HostPolicy()`) → global fallback. Uploaded keys live under `certs/services/<name>/`, not the DB. The base `tls.Config` must list `h2` in `NextProtos` or `http.Server` silently serves HTTP/1.1 only.
- **mTLS** (`services/mtls.go`, table `service_mtls`, CA at `certs/services/<name>/client-ca.pem`): `GetConfigForClient` only *requests* a cert (`RequestClientCert`, tickets off) for SNI names with a policy; `CheckClientCert` verifies per request against the **Host**'s policy, so SNI/Host mismatch can't bypass it. Required + no valid cert → 403 `mtls_required`, before the IP blocklist, trusted IPs included. `X-Client-Cert-*` are stripped and re-set on `r` itself, so the request log shows the fingerprint. No CRL/OCSP.
- `hostGuard` sends admin-path requests on a service host to the proxy, so the admin UI never appears on customer domains. It also enforces `--admin-allow` (client IP via `proxy.ClientIP`) and `--admin-listen` (issue #271): a refused request goes to the proxy pipeline as well, so every admin route must stay inside a group that uses `hostGuard`. The admin listener (`ui.AdminListener`) is plain HTTP, serves only the admin path and never proxies.

## WAF

- CRS is vendored in `internal/security/waf/crs/` (tag in `VERSION`), not the `coraza-coreruleset` module (stuck at v4.25.0). Update with `scripts/update-crs.sh <tag>`, stay on the LTS line, and add a `TestCRSBaseline` case per fixed bypass.
- `@coraza.conf-recommended` sets `SecRuleEngine DetectionOnly`; any `SecRuleEngine On` must come **after** the CRS includes or nothing is blocked.
- Body inspection is gated by Content-Type (`inspectionFor` in `waf/engine.go`). Without the gate, CRS 901340 makes Coraza parse binary bodies as URL-encoded forms (a 3.5 MiB PUT took 52s / 4.4 GiB). Multipart limit 12.5 MiB; everything else 128 KiB, enforced in `Check` because **Coraza ignores `SecRequestBodyNoFilesLimit`**. Uninspected bodies stream unread. Inspecting a buffered body over 8 KiB takes one of GOMAXPROCS process-wide slots (`inspectSlots`, issue #261); after a 2s wait `Check` returns `waf.ErrBusy` → 503 with `Retry-After`, logged unblocked as `waf_busy`. A body being buffered for inspection has a read deadline (`CheckOptions.SetReadDeadline`, 10s + size at 16 KiB/s, issue #272): too slow → `waf.ErrBodyTimeout` → 408 with `Connection: close`, not logged or scored. Uninspected bodies get no deadline.
- Rule exceptions and service-scoped custom rules are compiled in, so each affected service gets its own full CRS engine. `buildWAFAll` in `internal/app` builds the default + per-service engines lazily, re-run on SIGHUP and UI saves; `ReloadWAF` swaps them atomically. `AllowLargeJSUploads` is a packaged exception (skip JS bodies, except 911100/920420).
- Virtual patches (`waf/vpatch/*.conf`, embedded): one rule id each in 2000000–2099999, loaded **before** CRS so they deny under their own id and `SecRuleRemoveById` can still remove them. Turning one off is an ordinary rule exception. Autoban counts them as critical. How to add one: CONTRIBUTING.md.
- Custom rules (`waf_custom_rules`): `waf.ValidateCustomRule` — only `SecRule`/`SecAction`, ids in 1000000–1999999, standalone compile, unique ids. `buildWAFAll` skips invalid rows rather than failing startup.
- Verdict cache (`verdictcache.go`): 5s TTL, 4096 entries, per engine. Fingerprint covers IP, method, host, raw path/query, all headers and body. `Cookie`/`Authorization` are hashed like any header, so they're cached per exact value (issue #291). Hits/misses: `palisade_waf_verdict_cache_{hits,misses}_total`.
- Per-service request JSON Schema (`SetRequestSchema`, `off`/`log`/`enforce`): only on a fully buffered JSON-typed body; enforce → 400 `schema_violation`, log mode → action `schema_violation:log` (no stdout line per request).
- Per-service OpenAPI 3.x spec (`waf/openapi.go`, `SetOpenAPI`, table `service_openapi`): compiled into a route trie per engine build. Matched against `CheckOptions.Path` (service prefix stripped); `servers[].url` base paths are optional. Enforce → 404 route / 405 method / 400 params or body / 415 media type, action `openapi_violation`; log → `openapi_violation:log`. Declared operations skip the plain request schema. Undeclared `OPTIONS` passes (CORS) and `HEAD` falls back to `GET`.
- MCP endpoint guard (`waf/mcp.go`, `SetMCP`, table `service_mcp`, issue #234): structural checks on one Streamable HTTP path (service prefix stripped). A present `Origin` must be on the list, or match the Host when none are listed (no Origin = non-browser, passes). Only GET/POST/DELETE/OPTIONS; POST must be JSON-RPC 2.0 (object or batch, non-null id), with optional method allowlist (`prefix/*` wildcards) and `tools/call` tool allowlist. Body cap is the existing 128 KiB JSON limit. Enforce → 403 origin/method/tool, 405, 415, 400 envelope, action `mcp_violation`; log → `mcp_violation:log`. Runs before OpenAPI. No prompt-injection detection.
- Response inspection (`waf/response.go`, per service `response_inspect` ""/`log`/`block`): `CheckResponse` runs a fresh transaction (phase 1 replayed for CRS setup, then phases 3–4) from the proxy's `ModifyResponse` via `services.WithResponseHook`, never through the verdict cache. Only identity-encoded HTML/text/JSON/XML up to 64 KiB (~0.13 ms/KiB); the hook strips `Accept-Encoding` toward the backend (Go's Transport then gunzips transparently) and compression re-negotiates from the client's original. A match is a 950000–958999 rule **with a msg** (CRS flow/PL-gate rules match without one). `block` returns `services.ErrResponseBlocked` → 502, which the error handlers must not log, retry or count against backend health. Actions `response_leak:log`/`response_leak:block`.
- Coraza stops collecting arguments at `SecArgumentsLimit` (1000 per collection), so rule `waf.ArgsLimitRuleID` (2100000, loaded before CRS) answers 400 to anything over it (issue #292); without it the tail went uninspected. A rule exception for that id is the per-service escape hatch. `SecRxPreFilter On` (experimental in Coraza, must precede the rules) skips regexes whose required literals are absent; `TestRxPreFilterSameMatches` checks CRS matches the same rules either way.
- A failed body read returns `waf.ErrBodyRead` (client abort/malformed body) → 400 in the handler, never a 500 "waf error".
- No paranoia-level tiering: it would need one CRS engine per level per service.

## Storage

- Queries in `storage` use `?` and go through `DB.exec/query/queryRow`; build upserts with `upsertUpdate`/`upsertIgnore` (`sqlite.go`). `schema.go` is one statement per Exec; columns added later go in `schemaMigrations`.
- SQLite PRAGMAs go in the DSN (`_pragma=...`), not an `Exec` — only DSN params reach every pooled connection.
- **Never use SQLite `date()`/`strftime()` on `requests.ts`** — modernc stores Go's `.String()` format and they return NULL. Bucket times in Go with `>=`/`<=` (see `GetHourlyTraffic`). Always scan/insert timestamps as `time.Time`.
- Bolt-on features get new tables (`CREATE TABLE IF NOT EXISTS`) rather than `ALTER TABLE`, e.g. `waf_service_rule_exceptions`, `ip_threat_scores`, `ja4_reputation`.
- Config export/import (`configfile.go`, issue #263; `palisade config`, Settings "Configuration export", owner-only): JSON of the `configSteps` tables, both ways through a temp SQLite file and the same per-table copy code. The temp file seals with the source's key, so secrets stay `enc:v1:`; without a key any unsealed secret (meta secrets, webhook secret, TOTP columns) is blanked. Import refuses a DB that already has config unless `replace` (empties the config tables first), and checks column names against the real table. A new config table goes in `configSteps`; a new secret column outside meta goes in `secretColumns`.
- `--db` is the SQLite file; `checkSQLite` (`internal/app`) refuses a MySQL/Postgres `--db-driver` or DSN with the `config export`/`import` migration path (#300). `--db-driver` stays only so `--db-driver sqlite` in old units still works.
- `DB.Close` is idempotent and `QueueRequest` after it is a silent drop (a handler can outlive a timed-out shutdown); keep that guard if you touch the log queue.
- Pruning is not automatic unless `--prune-interval` is set; `PruneOldRequests` deletes in batches of 2000. `VACUUM` lives only in the one-shot `prune --vacuum`, never in the running server.
- **Secrets at rest** (`secretenc.go`, `--db-key-file`): AES-256-GCM with an `enc:v1:` prefix. A new secret meta key must go in `secretMetaKeys` and use only `getSecretMeta`/`setSecretMeta`. A sealed value read with a missing/wrong key must error loudly; `GetOrCreateChallengeSecret` must never regenerate on that error.

## Admin UI

- Session-cookie auth (bcrypt), optional TOTP/backup/email-code 2FA, passkeys, all per user in `admin_users` (`storage/users.go`; the old `meta` account is migrated in as owner on startup). One live session **per user**: `CreateSession` revokes that user's others (`revoked_at`, not delete). `sessions.token` holds SHA-256 of the cookie token (`storage.SessionID`, issue #269): `GetSession`/`ValidateSession` take the cookie value, every other session function and the device-list links take `Session.ID`. `sessionAuth` puts the user in the context (`currentUser`). Login is throttled per IP and per account (`loginlimit.go`); failed 2FA codes count too and are not reset by a correct password. Every path that sets a password (invite, change password, `setup`) goes through `ui.ValidateAdminPassword` (issue #273): 12+ characters, not the email, not in HIBP (5-char prefix only, fails open). bcrypt cost is `storage.PasswordCost` (12); `CheckAdminLogin` rehashes older hashes. UI tests use the harness's fake HIBP (`breachedTestPassword`), never the real one.
- **Roles** (`owner`/`admin`/`viewer`, issue #196): every mutating admin route is registered inside an `as(role, ...)` block in `Register`; `requireRole` enforces it and `TestRouteRoles` fails on an undeclared one. Owner = users, DB connection, secrets (webhook/email), API keys, backup. The last enabled owner can't be demoted, disabled or deleted (`ErrLastOwner`, in storage). Templates hide what a role can't use (issue #216) with `{{if can $.Role "admin"}}`, backed by the same `roleRank`; `renderPartial` adds `Role` to map data, so swapped fragments need a map. Viewers get settings in a disabled `<fieldset>` without `hx-post`, and the service View modal. `TestRolePageSweep` fails on any rendered write control or link whose route the role can't use.
- **Top bar search** (issue #225, `ui/search.go`, `components/search.html`): `GET {admin}/search?q=` over page cards plus live records (services, IP/geo rules, certs, feeds, custom rules). The card index is built once in `parseTemplates` (before any Execute) by walking each page's `content` parse tree: card headings come from `card-header`/`panel-header`/`section-head`/`settings-section-title` titles and literal `<h2>`/`<h3>`, and `{{if can .Role "x"}}` raises the role a card needs, through `{{template}}` calls. A new card component with a `Title` goes in `headerTemplates`. Card hits link `page#find=<title>`; `admin.js` scrolls to the matching `main h2/h3`.
- **User invites** (issue #229, `ui/users.go`, `storage/users.go`, table `admin_user_invites`): Add user takes only email + role and creates a password-less row; the token (SHA-256 in the DB, 7 days, single use, spent by DELETE) is emailed via `mailer.SendInvite` to that user's address, not the alert recipients. If sending fails the Users card shows the link once. `{admin}/invite/:token` is public, sets the password and starts a session. `CreateAdminUser` (initial password) is left for `setup` and tests.
- **OIDC SSO** (issue #197, `ui/sso.go`, `storage/sso.go`): invite-only. State, nonce and PKCE verifier ride in the `cz_sso` cookie, not server memory. The first login spends an `admin_sso_invites` row (needs `email_verified` true) and binds a new password-less user (or, for an existing user's email, that user with role and password kept, #296) to `iss`+`sub` in `admin_sso_identities`; later logins match on that pair, never on email. Email/groups missing from the ID token are filled from userinfo (Authelia's default). SSO logins skip Palisade 2FA and write an `SSO login` audit row with `amr`. Password login can't be turned off (break-glass). Tests use a fake IdP in `ui/sso_test.go`.
- **CSRF**: all non-GET admin routes. HTMX gets it from `hx-headers` on `<body>`. Plain `method="POST"` forms need `<input type="hidden" name="_csrf" value="{{.CSRF}}">`; raw `fetch` sends `X-CSRF-Token: document.body.dataset.csrf`. Anything returning sensitive data must be POST.
- **Audit log**: the `auditLog` middleware records every successful non-GET. A handler that returns 200 with an inline error must signal failure via a non-empty `...Err`/`...Error` template field or an `HX-Retarget` header. Summaries copy only the `auditFields` allowlist; never switch it to a denylist.
- **REST API** (`internal/ui/api.go`, `{admin}/api/v1/*`): bearer `cwaf_` keys stored as SHA-256 (not bcrypt — they're high-entropy), no session/CSRF. Read views for terminal clients (issue #243): `logs` (filters + limit/offset), `logs/:id`, `logs/stream` (JSON SSE, `: ping` every 30s, subscribed before headers), `stats` (incl. `top_blocked_ips`), `geo-rules`, `rule-exceptions`, `vpatches`. Writes for those three (issue #262): `POST`/`DELETE /geo-rules`, `POST /rule-exceptions` (global, or per service with `service`), `DELETE /rule-exceptions/global/:id` and `/rule-exceptions/services/:id` (the two tables have separate ids), `PUT /vpatches/:id` with `{"enabled": bool, "service"?}` (off = an ordinary rule exception). Unknown services are 400. Profiling: `{admin}/debug/pprof/` (`ui/pprof.go`, issue #267), owner role in the session group only, refuses cross-site `Sec-Fetch-Site` and `?seconds=` over 60. Metrics are at `{admin}/metrics` (session) and `{admin}/api/v1/metrics` (bearer; use this for Prometheus).
- `h.render` sets `data["Page"]` to the template name, so pagination uses `CurPage`.
- Go templates: content outside `{{define}}` never renders — modals go inside `{{define "content"}}`.
- Hidden-step wizards use `novalidate` + manual JS checks; `required` in a hidden step silently blocks submission in Chrome.
- Form controls use the `.field`, `.field-label`, `.btn-ghost` and `.tag` classes from `tailwind.css`, not long utility strings.
- Reuse partials in `templates/components/` (`card_header`, `panel_header`, `management_hero`, `empty_state`, `confirm_modal`, `toggle_switch`, `remove_btn`, `rule_type_badge`, `rule_ring_row`, `ring`, `section_head`, `pager`).
- Management pages (IP Rules, Geo Rules, Services, Certificates, WAF Rules, Threat Intel): `management-hero`, then one full-width `card border-t-4 border-t-edge p-5` primary-action card, supporting panels in a grid **below** it. Inline submit for single-row forms, button below for multi-row.
- Icons (issue #284): the embedded hugeicons font/CSS is a subset of the `hgi-*` names used in templates, `static/js/src` and `internal/ui` Go. After adding or removing an icon run `make icons` (full set cached in `.cache/hugeicons`, fonttools via `uvx`) and commit `internal/ui/vendor/hugeicons/`; `TestIconsInSubset` fails on a name missing from it, and `scripts/subset-icons.py` refuses one not in hugeicons. Flags: only ISO alpha-2 country flags; ones over 4 KB are 96x72 WebP (CSS points at `.webp`).

**JS/CSS**
- JS source in `static/js/src/`, minified to `static/js/dist/` (embedded). No Node/npm in this repo.
- Every page script/stylesheet tag carries `?v={{.Asset}}`: the stamp hashes every embedded asset, and a matching `?v=` gets `Cache-Control: immutable` for a year (`ui/static.go`, issue #255). An asset loaded without the stamp is never cached that way. `{admin}/static/*` is gzipped except fonts/images.
- Tailwind v4, CSS-first config in `static/css/tailwind.css`, compiled to committed `static/css/dist/tailwind.min.css`. **Re-run `make css` and commit when adding a class** anywhere under `internal/ui/` (templates and Go) or `static/js/src/`; classes elsewhere won't exist. After `make css`, a running browser may hold the old stylesheet.
- v3 "ledger" theme (issue #215): colors come only from the `--fn-*` variables in `tailwind.css`. `@theme` resets the palette (`--color-*: initial`), so only slate/red/green/amber/purple/violet/blue/sky/cyan plus the named tokens (`edge`, `side-*`, `success`/`warning`/`info`/`danger`) exist; any other family (rose, teal, …) compiles to nothing. Status colors: `-500` = bright (dots, badges), `-600`+ = text-safe ink shade. Text must pass WCAG AA on cream: `text-slate-500`+ and `text-<status>-600`+ only; `slate-300/400` and status `-400/-500` are for borders, dots, fills and placeholders.
- Use v4 names (`rounded-sm`, `shadow-xs`, `outline-hidden`, `bg-linear-to-*`), never v3 (`rounded`, `shadow`, `outline-none`, `bg-gradient-to-*`). Prefer `starting:` over JS animation.
- No `style="..."` or `<style>` for anything Tailwind can express. JS toggles `classList`, never `element.style`; keep a permanent `flex`/`block` next to a toggled `hidden`.

## Security subsystems

- **Bot** (`security/bot`, `challenge`): header scoring; trusted crawlers must verify by FCrDNS, ASN or pinned CIDR — UA alone is `unverified_crawler`. Operator pins come only from `--trusted-crawlers`; never hardcode IPs. JS PoW challenge + FingerprintJS (vendored, `/_cz/fp.js`) + automation detection; the `cz_bot_ok` pass cookie HMACs expiry + visitor ID + `ratelimit.ClientKey`, so `PassedChallenge`/`VisitorID`/`ServeVerify` take the client IP and a cookie from another IP (or /64) re-challenges (issue #312); optional Turnstile/hCaptcha fallback. `challenge.Exempt` skips the gate for web manifests (path-based, never header-based). Per-service `bot_mode`: `inherit`/`always`/`off`. **AI crawler policy** (`bot/ai.go`, `services/aicrawler.go`): per category `allow`/`challenge`/`block`, service override over the global default in `meta`; block hits any UA naming the category, allow needs a verified crawler (vendors without rDNS/ASN must be pinned via `--trusted-crawlers`, which merges into the existing entry). AI crawlers are never `IsTrustedCrawler`. **Web Bot Auth** (`bot/webbotauth.go`, issue #233): an RFC 9421 Ed25519 signature verifies a crawler only if the covered `Signature-Agent` origin is on that crawler's `sigAgents` (hardcoded `https://chatgpt.com` for OpenAI UAs, or `--trusted-crawlers ua=https://host`); other origins are never fetched (SSRF). Directories are fetched in the background (no redirects, 64 KiB, 1h OK / 5m fail); uncached = unverified. Tested against the draft's E.2 vectors.
- **TLS fingerprints**: JA4 only (JA3 was removed in #266; old DBs may still have an unused `requests.ja3_hash` column). Cloudflare `Cf-Ja4` wins only from Cloudflare peers. Per-connection geo/ASN caches store the client IP and discard on mismatch (pooled proxies multiplex clients).
- **Autoban** (`security/autoban`): scores events per IP in a window; `ip_blocked*`/`geo_blocked*` never score; cross-site subresource requests never score. Bans are `Auto-banned — ` notes on global block rules; existing admin rules always win; private IPs never banned. A ban is applied to the in-memory blocklist first (`IPBlocklist.Hold`, re-applied across `Reload` until `Release`), then written to the DB with retries (#260).
- **Threat score** (`security/threatscore`) feeds **adaptive enforcement** (`security/adaptive`, off by default). Adaptive actions log as `...:adaptive`, so anything matching actions must use prefix matches (`LIKE 'bot_challenge%'`, `strings.HasPrefix`), as must `ip_blocked`/`geo_blocked`/`rate_limited`.
- **Login protection** (`services/login.go`) and **honeypots** (`services/honeypot.go`, fire only on 404 responses).
- **Leaked password check** (`security/breach`, per service, login paths only): after the WAF, HIBP range API with only the 5-char SHA-1 prefix sent, 300ms timeout, **fails open**. `log` adds `X-Palisade-Leaked-Password: 1` to the backend request (client copies stripped); `block` → 403. Both score in autoban. The password must never reach a `RequestLog`.
- **Edge JWT** (`security/jwtauth`, table `service_jwt`, `Registry.JWT`, issue #279): after the gate, before the WAF, on protected path prefixes (service prefix stripped; open paths skipped). Trusted IPs are checked too (authentication, like mTLS), so the stage gates on `crawlerFile`, not `open`. Asymmetric algs only (RS*/PS*/ES*/EdDSA; HS* and `none` refused at save), `exp` required, 1 min leeway. Keys from a static PEM or a JWKS URL; the JWKS cache is shared per URL across reloads, never fetched on the request path, refetched on unknown kid at most every 30s via `egress.Client`. Enforce → 401 `jwt_invalid`; log → `jwt_invalid:log`; both score 1 point in autoban. The verified `sub` goes to the backend as `X-Auth-Subject`; client copies are always stripped when a policy exists.
- **Script inventory** (`security/csp`, tables `service_csp` + `csp_scripts`, issue #235): per service, `clientModify` adds `Content-Security-Policy-Report-Only` (admin policy + `report-uri`/`report-to` pointing at `/_cz/csp-report?s=<id>`) and `Reporting-Endpoints` to `text/html` responses only. The collector is a plain Echo route (never challenged, proxied or logged), always 204, 64 KiB body cap, per-`ClientKey` limit, 500 sources per service. It reads both `application/csp-report` and `reports+json`, keeps only `script-src*` violations, and records the origin (or `inline`/`eval`/`data:`) with the page path, query dropped. The first sighting fires the webhook (`csp_new_script`, category `scripts`, opt-in checkbox; source in `Host`) and `SendScriptAlert`. Enforce mode (issue #283, tables `csp_approved` + `service_csp_enforce`): sends `Content-Security-Policy` with the policy's `script-src` (`'self'` if none) plus the approved inventory entries (`csp.EnforcePolicy`; inline/eval map to the `unsafe-` keywords), same report endpoints, no report-only header. Unapproved sources are blocked and still reported for approval. Approvals are ticked in the CSP form and must be in that service's inventory; turning CSP off keeps them. The form warns when a source was first seen in the last 7 days and has a one-click "Return to report-only".
- **Per-path rate limits** (`services/raterules.go`, table `service_rate_rules`, issue #280): per service, one `METHOD /prefix rate burst` per line (`*` method, rate `N`/`N/s`/`N/m`/`N/h`), raw prefix match on the service path, longest wins, a named method beats `*`. After the per-service limit, skipped for open paths and trusted IPs; one `ratelimit.Limiter` per rule keyed by `ClientKey`, rebuilt on `Reload`. 429 logs `rate_limited:path <rule>`. The janitor only evicts buckets that have refilled, so slow rates aren't reset after 5 minutes idle.
- **Request policy** (`services/reqpolicy.go`, table `service_request_policy` on `Service.Policy`, issue #282, off by default): allowed methods (HEAD rides on GET), request Content-Types (`type/*` wildcards) and max body KiB per service. Stage 4.9, after the JWT check and before the WAF; skipped for open paths and trusted IPs. Enforce → 405/415/413 `policy_violation` (not scored by autoban); log → `policy_violation:log`. A body of unknown length is capped with `http.MaxBytesReader` while it streams. Presets (JSON API, HTML forms, Uploads) only fill the form, in `services.js`.
- **Cookie hardening** (`services/cookies.go`, table `service_cookie_policy`, issue #281, off by default): in the client-side response hook, adds `HttpOnly`, `SameSite=Lax` and (only when the client connection is TLS) `Secure` to backend `Set-Cookie`s missing them; listed cookie names are left alone. Stack headers (`X-Powered-By`, `X-AspNet*`, `X-Runtime`, `X-Generator`, `Via`, `X-Varnish`) are stripped from every service in `modify`.
- Rate limiter: in-process token bucket, persisted every 10s.
- Hot reload: `ReloadWAF`, `ReloadBotProtection`, `ReloadRateLimit` swap under RWMutex; SIGHUP rebuilds the WAF; SIGINT/SIGTERM shut down gracefully (10s) and drain the log queue. `main` cancels `app.Run`'s context on the signal; `serveUntil` drains the servers and returns only after that, because `Serve` returns as soon as `Shutdown` starts and the deferred `db.Close` would otherwise run under in-flight requests.
- In TLS mode the `:80` ACME/redirect listener is bound before serving, so a taken port fails startup rather than silently breaking cert renewal.

## Outbound

- Webhooks (`notify/webhook`): `generic`/`slack`/`discord` payloads; `generic` must stay byte-identical. Category logic is shared by `shouldSend` and formatting.
- Daily email (`notify/mailer`): Cloudflare Email Service only (endpoint and sender hardcoded); the token is never echoed back by the UI.
- Access log (`notify/accesslog`): nginx combined, in-house rotation. Close it after the DB drains (defer order in `serve`).

## Layout

`cli/` is a separate C++20 terminal client (issue #244): same version as the WAF (release passes `-DPALISADE_VERSION=<tag>`), installed by `install.sh` with `PALISADE_CLI=1` or `PALISADE_CLI_ONLY=1` (#253); CMake + FetchContent (FTXUI, cpp-httplib, nlohmann/json, versions pinned in `cli/CMakeLists.txt`), talks only to `/api/v1` with a bearer key, config `~/.config/palisade/config.toml` written 0600. Own workflow `cli.yml`, filtered on `cli/**`; Go tooling ignores the directory. Its test uses plain `assert` with `#undef NDEBUG` (default build type is Release). Everything under `internal/`: `config/`, `storage/`, `proxy/`, `services/`, `ui/`, `security/*` (pipeline signals and mitigations), `notify/*` (outbound reporting). `ui` and `storage` are split per feature (issue #264): `handlers.go` keeps the Handler, templates, auth middleware and `Register`; `db.go` keeps `DB`, `Open`, the log worker and `migrate`. Page handlers and queries live in `services.go`, `iprules.go`, `georules.go`, `wafrules.go`, `threatintel.go`, `certificates.go`, `settings.go`, `logs.go`/`requests.go`, `sessions.go`, etc.; add new code to the matching file, not back into `handlers.go`/`db.go`. `main.go` is only signal handling around `app.Run` (issue #287); everything it used to hold (flags, subcommands, server startup/shutdown, `buildWAFAll`) is in `internal/app`, which returns errors instead of exiting and is tested with listeners on port 0 (the `listening` hook reports the bound address). `assets.go` stays at the root because `//go:embed` can't reach `static/` otherwise; the FS values are passed in as `app.Assets`. `tools/minify` is build-time only. GeoLite2 country and DB-IP ASN databases are bundled via `//go:embed`. User docs live in a separate repo.

## Release and distribution

- `CHANGELOG.md` holds exactly `[Unreleased]` + the latest version. Add entries under `[Unreleased]` as one line: `- (#137) <issue title as on GitHub>` — no description, never a hand-written version heading. `make tag` rolls it (`scripts/roll-changelog.sh`) before tagging because CI reads release notes from the tagged commit.
- Docker: multi-stage → `scratch`; needs the copied CA bundle and `TMPDIR=/data` (Coraza writes a temp file; scratch has no `/tmp`). Runs as `USER 65532:65532` (issue #274); `/data` is created and chowned in the builder because scratch has no shell. Ports below 1024 need a mapping or `--cap-add NET_BIND_SERVICE`. `compose.yml` is `read_only` with all caps dropped, so anything written at runtime must live under `/data`. `checkWritable` in `internal/app` fails startup with the `chown` fix for a root-owned volume. Pushed to GHCR and Docker Hub on `v*` tags; tags are computed in shell, not `docker/metadata-action`.
- `deploy/install.sh` (`curl | sudo bash`): writes systemd units via heredoc and regenerates the main unit every run; extra flags go in `/etc/palisade/palisade.env` (`$PALISADE_FLAGS`), which is never overwritten. It generates `/etc/palisade/db.key` once. Both the server and prune units share the `SANDBOX` block (issue #275): `ProtectSystem=strict` with only `/var/lib/palisade` writable (plus `LogsDirectory` and a private `/tmp`), syscall/address-family filters and `UMask=0077`. Anything new the server writes at runtime must live under `/var/lib/palisade` or the log dir, or the unit needs a `ReadWritePaths=` entry.

Never commit credentials, TLS private keys, GeoIP databases or a production `waf.db`.
