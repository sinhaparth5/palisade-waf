Enable bot protection

Challenges clients whose anomaly score reaches the threshold below.

Score at which a challenge is issued. Scanners score ≥10; browsers typically score 0–2.

How long a solved challenge stays valid. 3600 = 1 hour.

Shown when a browser can't run the proof-of-work, e.g. over plain HTTP or with locked-down JavaScript. The token is verified with the provider before the bypass cookie is issued.

AI crawlers

Default for every service; each service can override it. Block refuses any client whose User-Agent names the category. Allow lets a crawler skip the challenge only once its source is verified: Meta's by network, OpenAI's, Anthropic's and Perplexity's after you pin their published IP ranges with --trusted-crawlers. Challenge needs bot protection on. robots.txt, sitemaps and llms.txt stay readable. Google-Extended and Applebot-Extended are robots.txt tokens, not crawlers; opt out of those in robots.txt.

Varnish Cache

Accelerate static assets and cache-eligible endpoints through a local Varnish daemon. Traffic is WAF-inspected first, then handed to Varnish with spoofable host headers scrubbed; cache misses return to the WAF, which routes them to the right backend automatically, so the Varnish config never needs editing when services change. Just enable caching per service on the Services page. Varnish is set up by the installer (or see deploy/varnish/README.md).
